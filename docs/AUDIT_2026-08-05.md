# Technical-lead audit — 2026-08-05

## Scope and evidence

- The imported engine was compared byte-for-byte with local upstream
  `mrbizarro/minimax-h3-mlx` at `2f5467dd41c5b632f39eca387cbd52919597e945`; it matched before this
  review's callback-only change.
- Architecture and task claims were checked against the MiniMaxAI/MiniMax-H3 model repository at
  `b3c7290e66afdf293bef3b9077b7a266ef421f34` and current ComfyUI
  `comfy_extras/nodes_minimax_h3.py`.
- No model was downloaded and no generation was run.

## Ranked findings

### Critical

1. The UI exposes only T2VA although the loader description implies broader full/quantized support.
   There is no adapter contract for FL2VA or Ref2VA, and checkpoint task metadata is not rejected
   before expensive loading.
2. Dropping the 13B AdaLN projections makes a warm pipeline schedule-specific. A later run with a
   different step schedule tries to rebuild from deleted projections. This must be corrected before
   warm reusable nodes are advertised as dependable.

### High

1. There was no cancellation or progress bridge inside the denoising loop. This review adds a
   host-neutral callback and a ComfyUI bridge; preview delivery still remains.
2. Swapping model specs retained the old pipeline while constructing the new one, creating an
   avoidable unified-memory peak likely to terminate ComfyUI. This review releases it first.
3. Dependencies omitted the directly imported `mlx-vlm` package and allowed an MLX/Pillow baseline
   older than the audited engine's upstream requirements. This review aligns the lower bounds.
4. Output prefix handling allowed absolute paths and `..` traversal outside ComfyUI output. This
   review confines targets to the output root. Collision-safe counters are still needed.
5. The current all-in-one output node writes only path strings and a sidecar. It does not return
   ComfyUI IMAGE/AUDIO/VIDEO contracts, UI preview descriptors, or embedded workflow metadata.

### Medium

1. Validation checks only directory existence, not component manifests, task support, shard/index
   completeness, quantization recipes, or free-memory headroom.
2. The engine accepts only 5–15 seconds while the current official model card says 4–15 seconds.
   Do not widen this until frame-grid and parity cases for the shorter boundary are verified.
3. Dimensions are aligned but unrestricted by aspect ratio, native 768-short-edge geometry, pixel
   cap, or memory estimate. Small defaults are correctly described as wiring tests, not quality.
4. Cancellation exceptions leave the pipeline resident by design and have no configurable failure
   cleanup policy. Intermediate lazy arrays should be audited with a tiny model.
5. Generation JSON omits checkpoint fingerprint, resolved frame count/duration, task/partition,
   component and quant recipes, software versions, and audio/video shape details.

### Low / packaging

1. Apache attribution existed only in documentation. This review adds a root NOTICE and identifies
   the exact engine source/revision. Model weights remain separately licensed and are not bundled.
2. ComfyUI Manager can clone the repository and install `requirements.txt`, but Registry publishing
   is not ready: there is no real PublisherId or `[tool.comfy]` block, no `.comfyignore`, and no
   clean-install compatibility job. A publisher identity must not be invented in source.
3. Requirements are compatibility lower bounds, not a reproducible lock. Keep broad bounds for a
   ComfyUI plugin, but test a known-good constraint set in CI and record it in releases.

## Boundary decision

Packing, scheduler, VAE, DiT, and text-encoder behavior remain in `minimax_h3_mlx`. ComfyUI paths,
progress/cancellation bridging, node schemas, output publication, and lifecycle policy remain in
`wee_todd_nodes`. No unrelated Phosphene, Spectrum, or KJNodes implementation was imported.
